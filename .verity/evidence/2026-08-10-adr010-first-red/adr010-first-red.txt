The first red of ADR-010's Verification table, observed before the repair and
in the same commit as the green.

Path normalisation, declared: the three probe scripts of blocks 1 and 2 were
written under $TMPDIR and are throwaway, so the `command:` lines below name
them as $TMPDIR/probe/<name> rather than by their absolute path. Only the
command lines are normalised. Every line inside a `---` block is the literal
stdout+stderr of the run as it happened, unmodified -- and none of it carries a
path, because the probes and the fixture print none by construction.

Block 3 is the fixture; blocks 1 and 2 are what license it. Block 1 measures
the defect against the launcher AT THIS BASIS, unedited, so the red of block 3
cannot be an artifact of the extraction that made the writer invocable. Block 2
measures that the extraction changed nothing.

===
BLOCK 1 -- the defect, measured against the UNCHANGED inline writer at basis.

The receipt writer at this basis is an inline unquoted heredoc at
scripts/launch_worker.sh:362-441 and cannot be invoked on its own. The probe
therefore takes lines 363-440 out of `git show HEAD:scripts/launch_worker.sh`
and runs them between the same unquoted <<PYEOF the launcher uses, so the shell
interpolation of $RUN_ID and friends happens exactly as it does in a real run.
Not one byte of the writer is edited.

Both arms are fed the two inputs ADR-010's Verification table declares: a
cc.json carrying the verbatim denial entry of ADR-010:54-56, and the same run
with permission_denials: [].

===
BLOCK 2 -- the extraction is pure.

ADR-010's Verification says both fixtures feed a constructed cc.json "to the
receipt writer". At basis there is nothing to feed, so the heredoc is extracted
into scripts/write_receipt.py -- the move ADR-002 D1/D2 made for the two launch
gates, for the same reason and in the same form: same branches, same messages,
same key order, one live implementation shared by the launcher and the tests.
Only the I/O contract changes; shell interpolation into a Python string literal
becomes an environment read.

Purity is asserted by output equivalence rather than by inspection: the
extracted unit and HEAD's heredoc are run over every branch the writer has --
cc_exit non-zero, all four gate verdicts, an empty gate object, a delta that is
non-empty and one that is empty, and an unreadable cc.json -- and their composed
receipts are compared byte for byte.

command: bash $TMPDIR/probe/purity.sh <repo>
---
same   [gate FAIL, denials present]
same   [gate FAIL, denials empty]
same   [gate PASS, delta non-empty]
same   [gate PASS, delta empty (NO_OP)]
same   [gate STOP (absent criterion)]
same   [gate NO-VERDICT]
same   [empty gate object]
same   [cc_exit=124 (gate skipped)]
same   [unreadable cc.json]
-- extraction purity: cases=9 differing=0
---

BLOCK 3 -- the fixture, red, against the extracted but UNREPAIRED writer.

scripts/write_receipt.py at this point is the extraction and nothing else: it
composes exactly what block 1's heredoc composed. Block 2 is what makes that a
measured statement rather than a claim.

fx-refusal-control is UNMEASURED here, not red, and that is the row's declared
posture: ADR-010:181-184 says the control "cannot be red before the change, and
that is the point". With no refusals object in the writer's output at all,
there is no field whose discrimination could be measured. The fixture reports
the suite's third state rather than a pass or a fail, and exits 2 on it -- the
same convention tests/run_tests.sh:5-9 defines.

command: bash tests/adr010_refusal_fixture.sh
